## Етап 1: Система коментарів 💬

**Дата:** 2026-10-10

### Що зроблено
Додано повноцінну систему коментарів до статей із можливістю CRUD операцій.

### Зміни у базі даних
- **prisma/schema.prisma** — додано модель `Comment` з полями: `id`, `content`, `articleId`, `authorId`, `createdAt`, `updatedAt`
- Зв'язки: `Comment → Article` (onDelete: Cascade), `Comment → User` (onDelete: Cascade)
- Додано поле `comments Comment[]` до моделей `User` та `Article`

### Нові API endpoints
| Метод | Шлях | Опис | Доступ |
|-------|------|------|--------|
| GET | `/api/articles/[id]/comments` | Список коментарів до статті | Публічний |
| POST | `/api/articles/[id]/comments` | Створити коментар | Авторизований |
| DELETE | `/api/comments/[id]` | Видалити коментар | Лише автор коментаря |

### Нові файли
| Файл | Опис |
|------|------|
| `src/app/api/articles/[id]/comments/route.ts` | API для GET/POST коментарів |
| `src/app/api/comments/[id]/route.ts` | API для DELETE коментаря |
| `src/hooks/useComments.ts` | SWR хук для завантаження коментарів |
| `src/components/Comments/CommentForm.tsx` | Форма для додавання коментаря |
| `src/components/Comments/CommentList.tsx` | Список коментарів з skeleton-loading |
| `src/components/Comments/CommentsSection.tsx` | Обгортка: форма + список |

### Змінені файли
| Файл | Зміна |
|------|-------|
| `prisma/schema.prisma` | Додано модель Comment, оновлено User та Article |
| `src/types/index.ts` | Додано інтерфейси `Comment`, `CommentAuthor` |
| `src/app/(main)/articles/[id]/page.tsx` | Інтегровано `CommentsSection` під контентом статті |

### Ключові моменти
1. **Валідація**: коментар не може бути порожнім, максимум 1000 символів
2. **Авторизація**: тільки автор може видалити свій коментар (перевірка `authorId`)
3. **Cascade delete**: при видаленні статті або юзера — всі їхні коментарі видаляються автоматично
4. **SWR mutate**: після створення/видалення коментаря список оновлюється через `mutate()`
5. **Skeleton loading**: відображається анімований скелетон під час завантаження

## Етап 2: Пошук, фільтрація та пагінація 🔍

**Дата:** 2026-10-10

### Що зроблено
Додано серверну пагінацію, повнотекстовий пошук та фільтрацію статей за категоріями.

### Зміни в API
- **GET `/api/articles`** тепер підтримує query-параметри:
  - `?search=query` — пошук за title та content (case-insensitive)
  - `?category=Програмування` — фільтрація за категорією
  - `?page=1&limit=9` — серверна пагінація (skip/take)
- Відповідь змінено на формат `PaginatedResponse<Article>`
- Використано `Promise.all([findMany, count])` для паралельного виконання

### Нові компоненти
| Файл | Опис |
|------|------|
| `src/components/SearchBar.tsx` | Поле пошуку з debounce 400мс |
| `src/components/CategoryFilter.tsx` | Горизонтальний скролл з chip-кнопками категорій |
| `src/components/Pagination.tsx` | Пагінація з номерами сторінок та ellipsis |

### Змінені файли
| Файл | Зміна |
|------|-------|
| `src/app/api/articles/route.ts` | GET: додано search, category, page, limit |
| `src/hooks/useArticles.ts` | Приймає параметри, повертає PaginatedResponse |
| `src/types/index.ts` | Додано `PaginatedResponse<T>` |
| `src/app/(main)/articles/page.tsx` | Переписано з новими компонентами |

### Ключові моменти
1. **Debounce**: пошук через 400мс після останнього натискання
2. **Скид сторінки**: при зміні фільтрів page → 1
3. **Лічильник**: "Знайдено X матеріалів"
4. **SWR ключ**: динамічно з URLSearchParams

## Етап 3: Адмін-панель з ролями користувачів 🛡️

**Дата:** 2026-10-11

### Що зроблено
Додано повноцінну систему ролей (RBAC) та адмін-панель для управління платформою.

### Зміни у базі даних
- Додано `enum Role { USER, ADMIN }` у Prisma schema
- Додано поле `role Role @default(USER)` до моделі `User`
- ⚠️ **Міграцію потрібно запустити**: `npx prisma migrate dev --name add_roles_and_comments`

### Зміни в аутентифікації
- **src/auth.ts** — розширено типи NextAuth (User, Session, JWT) полем `role`
- JWT callback зберігає та передає роль, з fallback перевіркою в БД
- Session callback додає `session.user.role`
- Credentials authorize повертає роль користувача

### Хелпер безпеки
- **src/lib/admin.ts** — функція `requireAdmin()`:
  - Перевіряє авторизацію та роль `ADMIN` безпосередньо в БД
  - Захист від підміни JWT токена

### Нові API endpoints
| Метод | Шлях | Опис | Доступ |
|-------|------|------|--------|
| GET | `/api/admin/stats` | Статистика: кількість юзерів/статей/коментарів + 5 останніх юзерів | ADMIN |
| GET | `/api/admin/users` | Список користувачів з пагінацією та пошуком | ADMIN |
| PATCH | `/api/admin/users/[id]` | Зміна ролі юзера (з захистом від самопониження) | ADMIN |
| DELETE | `/api/admin/users/[id]` | Видалення юзера (з захистом від самовидалення) | ADMIN |
| GET | `/api/admin/articles` | Список статей для модерації з пагінацією | ADMIN |
| DELETE | `/api/admin/articles/[id]` | Видалення будь-якої статті адміном | ADMIN |

### Нові сторінки UI
| Файл | Опис |
|------|------|
| `src/app/(main)/admin/page.tsx` | Дашборд: картки статистики, останні юзери, навігаційні посилання |
| `src/app/(main)/admin/users/page.tsx` | Таблиця юзерів: пошук, зміна ролі (select), видалення, пагінація |
| `src/app/(main)/admin/articles/page.tsx` | Таблиця статей: пошук, перегляд, видалення, пагінація |

### Змінені файли
| Файл | Зміна |
|------|-------|
| `prisma/schema.prisma` | Додано enum Role, поле role у User |
| `src/auth.ts` | Розширено типи, callbacks передають role |
| `src/proxy.ts` | Додано `/admin/:path*` до matcher |
| `src/components/Navigation/Navigation.tsx` | Додано секцію "Адміністрування" (умовно для ADMIN) |

### Ключові моменти
1. **RBAC**: дворівнева система ролей USER/ADMIN
2. **Безпека API**: `requireAdmin()` перевіряє роль в БД, а не тільки в JWT
3. **Захист від самознищення**: адмін не може видалити себе або понизити свою роль
4. **Proxy (Next.js 16)**: `/admin/:path*` захищений від неавторизованого доступу
5. **Умовна навігація**: секція "Адміністрування" видима тільки для ADMIN
6. **Клієнтська перевірка**: сторінки адміна показують "Доступ заборонено" для non-ADMIN

## Етап: виправлення помилок та редизайн 🎨

**Дата:** 2026-10-11

### Знайдені й виправлені помилки
| Проблема | Наслідок | Виправлення |
|----------|----------|-------------|
| `* { margin:0; padding:0 }` у `globals.css` стояв поза шарами Tailwind v4 | Перебивав усі утиліти `p-*`, `m-*`, `space-*`, `mx-auto`; інтерфейс виглядав «зліпленим» | Reset прибрано (є в Tailwind Preflight), базові стилі винесено в `@layer base` |
| `SearchBar` викликав `onChange` у `useEffect` із нестабільною залежністю | Через ~400 мс після переходу на сторінку 2 пагінація поверталась на 1 | Debounce перенесено в обробник події; фільтри й сторінка зберігаються в URL |
| Статтю без автора могли змінювати/видаляти всі авторизовані | Діра в авторизації | Тільки автор або адміністратор; для «безхазяйних» статей — лише адміністратор |
| Адміністратор не міг видаляти чужі коментарі | Модерація не працювала | `DELETE /api/comments/[id]`: автор або адміністратор |
| `page=abc`, `limit=100000` у `GET /api/articles` | `NaN` → 500 або вибірка всієї таблиці | `parsePagination` (limit ≤ 50) |
| `validateArticle`/`validateRegister` не використовувались в API | Будь-які дані в БД, довільна категорія | Валідація в `POST/PATCH /api/articles` і `/api/register` |
| Email чутливий до регістру | `A@x.com` і `a@x.com` — різні акаунти | Нормалізація до нижнього регістру при реєстрації й вході |
| У схемі з'явились `Role`, `Comment`, але міграції не було | `prisma migrate deploy` на чистій БД падав | Додано міграцію `20261011090000_add_roles_and_comments` + індекси |
| У seed не було адміністратора | Адмін-панель була недосяжна | `admin@studyhub.com` / `admin12345` + демо-коментарі |
| 10 помилок ESLint (`any`, `prefer-const`, setState в effect) | Падав `npm run lint` у CI | Типізовано через `Prisma.*WhereInput`, `unknown` у `catch` |
| Застарілі тести (`Переглянути →`, `Можливості платформи`, неоднозначний селектор кнопки) | Падали Jest і Playwright | Тести оновлено, додано нові (пагінація, плюралізація, права) |

### Нове оформлення — «зошит у клітинку»
- Палітра: папір, синє чорнило, жовтий маркер, червоне поле зошита (токени в `globals.css`).
- Шрифти: Onest (інтерфейс) і Literata (читання статей), self-hosted через `@fontsource-variable`.
- Нова шапка з навігацією, мобільна нижня навігація, футер; бічну панель прибрано.
- Головна: блок «Нове в зошиті» й теми з лічильниками (дані з Prisma у серверному компоненті).
- Список: пошук, фільтри та сторінка в URL, лічильник результатів, скидання фільтрів.
- Стаття: аркуш із червоним полем, час читання, коментарі з підтвердженням видалення.
- Доступність: видимий фокус, `aria-*`, `prefers-reduced-motion`.
